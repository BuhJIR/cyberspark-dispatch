The Disk Illusion

Почему пассивный бэкап парализует нейросеть и взрывает API лимиты

362 мегабайта данных в оперативной памяти fstoram: 18 баз SQLite и 1951 микро-файл. Одно выключение питания — и всё растворяется в кремнии.

Попытка слепо синхронизировать эту свалку в Google Drive намертво застряла на 20%: API Google накладывает барьер в 2-3 запроса в секунду. 1500 микро-логов превратили процесс в бесконечный поллинг.

Анатомия сбоя локальной гравитации

Burn On Touch

Шлюз, который уничтожает себя в оперативной памяти при первом контакте

Обычные Signed URL живут часами и допускают многократный слив. В контуре Спарка ссылка обязана быть буквально одноразовой.

При поступлении любого входящего сокета сервер Спарка выполняет атомарный activeLeases.delete(token) в RAM до отправки первого байта полезной нагрузки.

Атомарная физика сокета в RAM
[ Входящий HTTP GET/HEAD ]
│──► token = activeLeases.get(id)
│──► activeLeases.delete(id) // СОЖЖЕНО В ОЗУ
└──► Stream payload (Pipe напрямую в сокет)

Второй попытки не существует. Если скачивание прервано — шлюз мертв. Агент обязан захватить поток в тот же миллисекундный квант без сохранения токена на диск.
